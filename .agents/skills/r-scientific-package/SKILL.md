# R Scientific Package & Research Compendium Guide

This skill provides an end-to-end blueprint for developing, auditing, and publishing an R package that accompanies a scientific research paper, dissertation, or thesis. It prevents common pitfalls in cross-platform encoding, GitHub LaTeX rendering, author attribution, and `R CMD check` compliance.

---

## 1. Dual Nature: Package vs. Research Compendium

A modern scientific software project serves two simultaneous roles:
1. **An Installable R Package:** Clean, portable, documented library code that users install via `remotes::install_github("User/repo")` or CRAN.
2. **A Reproducible Research Compendium:** Standalone scripts, raw/processed data, figures, and simulation routines that replicate every table, number, and plot in the published paper.

### Standard Directory Hierarchy

```text
<repository-name>/
├── .agents/
│   └── skills/
│       └── r-scientific-package/
│           └── SKILL.md
├── .Rbuildignore             # Prevents research compendium assets from polluting package build
├── DESCRIPTION               # Package metadata and dependencies
├── NAMESPACE                 # Exported functions and imported directives
├── LICENSE                   # Software license (e.g., GPL-3)
├── R/                        # Exported and internal R functions
├── data/                     # Packaged, ready-to-load datasets (.rda)
├── data-raw/                 # Raw datasets (.xlsx, .csv) & data preparation scripts
├── figures/                  # Publication figures in vector formats (SVG, PDF, EPS)
├── inst/
│   └── CITATION              # Dual citation directives (package vs. journal paper)
├── man/                      # Rd documentation files (generated by roxygen2)
├── scripts/                  # Standalone reproducible execution scripts
│   ├── case_study_analysis.R # Empirical application & model comparison
│   ├── generate_figures.R    # Generates all article figures
│   ├── run_simulation_study.R# Monte Carlo simulation routines
│   └── run_tests.R           # Standalone unit test suite runner
├── simulations/              # Pre-computed Monte Carlo simulation results (.rds)
└── tests/
    ├── testthat/             # Unit tests (test-*.R)
    └── testthat.R            # Test runner
```

## 2. Authorship & Citation Architecture

Scientific packages frequently face a dilemma: the **R package code** is authored by the developer, whereas the **scientific paper** is co-authored by advisors and collaborating researchers.

### Rules of Separation:
1. **`DESCRIPTION` File:**
   - Only list the actual developer(s) of the software package in `Authors@R`:
     ```dcf
     Authors@R: 
         person(given = c("GivenName", "MiddleName"),
                family = "FamilyName",
                role = c("aut", "cre"),
                email = "author@example.com")
     ```
   - Role `aut` = Author, `cre` = Maintainer (Creator).

2. **`inst/CITATION` File:**
   - Define two distinct `bibentry()` calls:
     ```r
     bibentry(
       bibtype = "Manual",
       title = "PackageName: Title of the Package",
       author = person(given = c("Given", "Middle"), family = "Family", email = "author@example.com"),
       year = "2025",
       note = "R package version 0.1.0",
       url = "https://github.com/User/repo",
       textVersion = "Family, G. M. (2025). PackageName: Title of the Package. R package version 0.1.0, https://github.com/User/repo.",
       header = "To cite the 'PackageName' package in publications, please use:"
     )

     bibentry(
       bibtype = "Article",
       title = "Full Title of the Research Paper",
       author = c(
         person(given = c("Given1", "M1"), family = "Family1"),
         person(given = c("Given2", "M2"), family = "Family2")
       ),
       journal = "Journal Title (or Under Review)",
       year = "2026",
       textVersion = "Family1, G. M., & Family2, G. M. (2026). Full Title of the Research Paper. Journal Title.",
       header = "To cite the underlying research methodology and case study, please use:"
     )
     ```

3. **`README.md` File:**
   - Use `## Author` (singular) for the package developer.
   - Use `## Citation` with distinct subsections:
     - `### Package Reference` (with BibTeX `@manual`)
     - `### Research Paper Reference` (with BibTeX `@article`)
     - `### Master's Dissertation / Thesis` (with BibTeX `@mastersthesis`)

## 3. Windows-Proofing: Cross-Platform Graphics & Encoding

### The Danger:
On Windows, default R graphics devices (`pdf()`, `png()`, `postscript()`) operate under single-byte encodings (e.g., Latin-1 / Windows-1252). If ggplot2 themes, default function parameters, or factor levels include raw UTF-8 Unicode characters (such as `μ`, `σ²`, `Δ`, `ρ`), execution crashes with:
```text
Error in grid.Call(C_textBounds, as.graphicsAnnot(x$label), ...): 
  mbcsToSbcs: conversion failure from 'UTF-8' to 'latin1'
```

### Mandated Coding Standards:
1. **Never use raw Greek/math Unicode in default function arguments:**
   - ❌ Bad: `plot_drift(drift, x_label = "Tempo", y_label = "μt")`
   - ✅ Good: `plot_drift(drift, x_label = "Time", y_label = "Degradation")`
2. **Use `bquote()` or `expression()` for mathematical axes and legends:**
   - ✅ Good:
     ```r
     labs(
       x = bquote(bold("Time") ~ (t)),
       y = bquote(bold("Degradation") ~ Y(t)),
       color = bquote("Parameter" ~ mu)
     )
     ```
3. **Avoid raw Unicode in `factor()` levels or dataframe labels:**
   - ❌ Bad: `levels = c("μ = 0.5", "μ = 1.0")`
   - ✅ Good: `levels = c("mu = 0.5", "mu = 1.0")` and format them dynamically in ggplot2 with `label_parsed` or `label_bquote()`.
4. **Documentation files (`.Rd`):**
   - Use standard roxygen2 LaTeX markup `\eqn{\mu}` or plain ASCII (`mu`, `sigma^2`) instead of raw Unicode symbols.

## 4. GitHub Flavored Markdown (GFM) LaTeX Standards

GitHub uses MathJax / KaTeX to render math in `README.md`. It has strict parsing rules:

1. **Display Equations ($$):**
   - The opening `$$` and closing `$$` **must** be on their own separate lines.
   - They **must** be surrounded by blank lines above and below.
   - ❌ Bad:
     ```markdown
     $$X(t) = \mu t + \sigma B(t)$$
     ```
   - ✅ Good:
     ```markdown
     $$
     X(t) = \mu t + \sigma B(t), \quad t \ge 0
     $$
     ```
2. **HTML Blocks & Figure Captions:**
   - Inside HTML elements like `<p align="center">` or `<em>...</em>`, raw LaTeX formulas like `$\mu$` often fail to parse or break HTML tags.
   - Always use **HTML entities**:
     - `&mu;` for $\mu$
     - `&sigma;<sup>2</sup>` for $\sigma^2$
     - `&rho;` for $\rho$
     - `&Delta;` for $\Delta$
     - `<i>t</i>` for $t$
     - `&le;` and `&ge;` for $\le$ and $\ge$

## 5. Cleanliness & Transience Prevention

1. **Preventing `Rplots.pdf` in Tests and Scripts:**
   - Running ggplot2 or base graphics commands non-interactively creates an unwanted `Rplots.pdf` file in the working directory.
   - In test files and runner scripts, always add an automatic cleanup exit handler:
     ```r
     on.exit({
       if (file.exists("Rplots.pdf")) unlink("Rplots.pdf")
     }, add = TRUE)
     ```
2. **Comprehensive `.Rbuildignore`:**
   - Keep non-package compendium files out of the package build:
     ```text
     ^.*\.Rproj$
     ^\.Rproj\.user$
     ^figures$
     ^data-raw$
     ^simulations$
     ^scripts$
     ^LICENSE$
     ^\.agents$
     ```

## 6. Verification & Quality Assurance Protocol

Before publishing, tagging, or submitting, execute the full validation cycle:

```powershell
# 1. Update Rd documentation and NAMESPACE
& "C:\Program Files\R\R-4.6.1\bin\Rscript.exe" -e "roxygen2::roxygenize()"

# 2. Run unit tests
& "C:\Program Files\R\R-4.6.1\bin\Rscript.exe" scripts/run_tests.R

# 3. Build source package tarball
& "C:\Program Files\R\R-4.6.1\bin\R.exe" CMD build .

# 4. Check package with CRAN standards (Target: 0 ERRORS, 0 WARNINGS, 0 NOTES)
& "C:\Program Files\R\R-4.6.1\bin\R.exe" CMD check --no-manual --no-build-vignettes <PackageName>_<Version>.tar.gz

# 5. Clean up build artifacts
Remove-Item -Force <PackageName>_<Version>.tar.gz
Remove-Item -Recurse -Force <PackageName>.Rcheck
```

## 7. Paper Synchronization Checklist

When aligning an R package with a submitted paper:
- [ ] Ensure the repository name on GitHub matches the URL in the paper's **Data Availability** statement.
- [ ] If renamed, update `git remote set-url origin <new-url>`.
- [ ] Update `URL` and `BugReports` in `DESCRIPTION`.
- [ ] Update badges and install instructions in `README.md`.
- [ ] Update repository URLs in `inst/CITATION`.
- [ ] Ensure all 17+ paper figures are generated in vector formats (`.svg`, `.pdf`, `.eps`) in `figures/`.
- [ ] Lock random seeds (`set.seed()`) in scripts so diagnostic tests (e.g., Anderson-Darling p-values) match the published manuscript numbers exactly.
